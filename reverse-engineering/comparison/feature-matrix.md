# 功能对照表

## 1. 任务书要求的对照表

| 功能 | 游戏1（Just Xiangqi） | 游戏2（Just Go） | 是否共用 |
|---|---|---|---|
| 棋盘交互 | 9×10 中国象棋棋盘，点击/拖拽，合法着法提示，动画 | 19/9 路围棋棋盘，落子、提子、数目（日志与 SGF 证实规则） | 否（棋种不同；交互范式相似）[推测] |
| AI 引擎 | 三路：NativeAI、ElephantEyes(C#)、Pikafish(UCI) | 单路：KataGo(GTP) | **否** [已验证] |
| 难度系统 | 13 档（0–12）+ 生涯 16 档，显式配置 | 未知（配置缺失） | 否 / 无法判定 |
| 局面估值 | 子力+位置表 → 预计算知识表 → NNUE | KataGo policy/value 网络 | **否** [已验证] |
| 棋谱系统 | `.game` Odin JSON + PGN 导出 | `.sav` Odin JSON + SGF | 设计同构，实现不共用 [有证据支持] |
| 逐手分析 | `MoveAnalysis`（cp/mate/wdl）+ `Report` 标签 | `WhiteLeadScores` + `WhiteWinRates` + ownership | 思路同构，数据不共用 [有证据支持] |
| 棋局回放 | `Local_Review`，逐步前进/后退、箭头、评分图标 | SGF/存档回放（日志与数据结构证实，界面未见） | 思路同构，实现独立 [推测] |

## 3. 共用性总结

| 层次 | 共用程度 | 证据强度 |
|---|---|---|
| 平台接入（Steam） | 高 | 强 |
| 序列化/存档 | 高（同 schema 风格） | 强 |
| UI 插件与交互范式 | 中（推测） | 弱 |
| 棋谱/复盘设计 | 中（同构） | 中 |
| AI/搜索/估值 | 无 | 强 |
| 难度机制 | 无（game-02 未知） | 强/缺失 |

## 4. 结论

两款游戏可以抽象出**一套通用的“棋类陪练产品骨架”**（对局、存档、复盘、分析、提示、训练、平台），但**不能抽象出通用的棋类 AI 内核**。四国军棋应复用“骨架”的设计思路，重写规则、搜索与估值。
